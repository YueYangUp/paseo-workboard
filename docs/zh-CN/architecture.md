# 架构

[English](../architecture.md) · [README](../../README.zh-CN.md)

Workboard 是受信任的 Paseo 插件，客户端和服务端使用独立入口。daemon 负责保存任务数据和执行自动化；客户端展示所选 host 的看板或分组列表，仅在本地保存显示偏好。

## 模块

| 位置                                              | 职责                                             |
| ------------------------------------------------- | ------------------------------------------------ |
| `index.client.tsx`                                | 侧栏、设置页、Command Center 入口和查询 provider |
| `client/`                                         | 看板与列表、表单、筛选、拖拽、主题和翻译         |
| `index.server.ts`                                 | 注册设置、RPC handler 与服务端生命周期           |
| `server/workboard.ts`                             | 对账、串行变更、绑定、置顶和归档决策             |
| `server/host.ts`                                  | Paseo 清单、订阅、历史和 workspace 操作          |
| `server/paseo-compat.ts`                          | 桥接公开 SDK 尚未提供的宿主操作                  |
| `server/conversations.ts`、`server/git-safety.ts` | 对话时间与归档前检查                             |
| `server/store.ts`、`shared/migrations.ts`         | revision 校验保存与数据迁移                      |
| `shared/model.ts`、`shared/rpc.ts`                | Zod 模型、设置与 RPC 契约                        |

## 身份与状态

任务使用插件生成的 ID。未绑定草稿没有 `workspaceId`，绑定后的任务由 host 与 workspace ID 唯一确定。名称、分支和路径不用于确定身份；一个 workspace 内多个 Agent 仍只有一张卡片。

daemon 分页导入全部活跃 workspace。没有受管理分组标签的 workspace 进入配置的默认分组，未配置、配置失效或指向终态时回退到首个待归类组，导入时不写标签；默认落点排除已完成/已废弃；保存终态默认落点或将已选默认组改为终态时拒绝，但存储 schema 不因此拒绝存量数据。显式标签决定分组，同时存在多个分组标签时展示冲突。普通标签保留。安装前已归档且插件从未观察过的 workspace 不会补录。

每个分组有稳定 ID、名称、受管理标签、业务类型与可选颜色。显示顺序和颜色独立于类型；类型决定草稿落点、进行中侧栏置顶和终态归档资格。至少各保留一个待归类、待开始和已废弃类型组；删除分组区分任务占用和默认落点占用，分别要求移走任务或更改默认分组。新草稿默认落点可选择任意待开始类型组；配置缺失或失效时保留按类型选首组的回退。 开始工作独立解析 `defaultStartWorkGroup`：有效配置的进行中组优先，再取首个进行中组，没有则无目标。StartModal 与服务端共用该解析函数，保留待完成绑定与本次显式 stage 意图。`defaultStartGroup` 仅用于未标记 workspace 导入。缺少开始工作偏好时初始化为 null，不复制导入默认值；ID/类型校验放在设置写入边界，无效存量偏好仍可读取。客户端删除提示与服务端校验均要求先更换显式选定的工作默认组，才能删除该组或改其类型。

Agent 活动单独展示，回复结束不会把任务标为完成。workspace 只聚合未归档、非委派的 Agent，按 waiting、error、attention、running、idle 的顺序取状态。目录 inventory 和订阅 upsert 都将 Paseo 的 `paseo.parent-agent-id` 标签映射为 `Agent.delegatedBy`。`delegatedBy` 非空的 Agent 不参与该聚合，运行状态也不例外；卡片活动、活动筛选和需关注的活动原因均使用这一结果。provider 子 Agent 使用 `parentAgentId`，仍参与聚合。

在参与聚合的 Agent 中，只有原生 Agent 的 `status: idle`、`lastError` 非空且关注原因不是 error，并且另一个参与聚合、未报错 Agent 的 `lastUserMessageAt` 严格晚于报错 Agent 的 `updatedAt`，才在聚合中排除该错误。后者只作为错误时间的上界，不能证明健康活动，因为元数据修改也会推进它。证据无效或缺失时保留错误。该范围内的原生 error 状态、error 关注原因、失败的 provider 子 Agent 和来源不明的错误继续计入需关注。包括委派 Agent 在内，各 Agent 详情均保留原始活动状态。委派 Agent 也仍参与对话证据和归档安全检查；其运行或等待状态仍会推迟归档。PR/MR 信息来自 Paseo workspace 数据；Workboard 不额外轮询 forge，也不实现另一套合并检测。

## 保存与并发

host settings 使用 schema version 10（在 `shared/model.ts` 中单处声明），保存任务、分组、偏好、绑定/归档意图和插件拥有的置顶时间戳。对话记录把展示证据与门禁证据分开保存；归档规则各自携带期限；默认落点按用途分别保存；合并草稿按任务记录。Store 校验数据，并以宿主 settings revision 为基线保存。迁移保留既有记录；不支持或损坏的数据会阻止正常初始化、停止自动重试，并通过看板错误提示展示原因；连接等瞬时错误仍每 10 秒重试。数据不会被静默替换。

迁移数据缺少状态标签互斥偏好时，先关闭互斥并持久化待检测标记。首次成功获取完整 workspace 清单后进行一次判断：任一 workspace 的受管理标签有冲突则保持关闭，全部无冲突则开启。同步复用现有标签解析过程，在自动处理标签前将判断结果与任务状态一起保存。清单读取失败时保持待检测；写入结果未确认时重新加载持久化状态，判断结果已保存则不再检测，未保存则继续等待检测。已有明确偏好原样保留，新数据默认开启。

每个迁移都是 `shared/migrations.ts` 链路中的纯函数步骤，对当前数据必须幂等，并且必须让旧记录仍然可用。规则如下：

- 不得丢弃仍携带信息的记录，也不得编造旧值无法证明的数据。没有观测时间或 provider 子 Agent ID 的 Agent ID 仅在仍是未填充占位时清理；已缓存的子 Agent 即使缺少消息时间或存活标记，也保留其条目。
- 各状态归档规则由既有共享值映射得到：每条规则保留 `autoArchive && ruleEnabled`，并保留全部期限，因此迁移后的 workspace 仍可能具备自动归档资格；新设置默认两条规则均关闭。
- 只有在迁移无法检查宿主状态的具体修复中，含义不明的归档偏好才向更保守方向处理：当设置记录缺少已废弃组时，v6→v7 补建一个并把自动归档关闭，因为无法判断已有 workspace 是否本应已废弃；持久化的 `archiveMappingNeedsReview` 标记会持续显示该说明，直到通过到期任务确认流程重新开启。其它迁移保留原有偏好。补建分组时保留已有分组、任务及顺序。
- 存储结构或含义变化时必须提升 schema 版本，并为该步骤补充从每个可接受版本出发的迁移测试。

两种视图共用的任务顺序位于 v8 Data 与 Board 顶层的 `cardOrderByStage`，与任务记录和设置分开。客户端与服务端共用纯排序函数。reorder/reset 在服务端串行队列和 Store update 内比较完整、未筛选的投影列；只隐藏 archived/external 记录，pending/uncertain 归档与绑定任务保留为不可移动邻居。重排只移动一个可用任务并保持其它任务相对顺序，只写顺序映射。缺席 ID 暂时忽略，回列时恢复位置；下一次手排压实当前成员，删除分组清除其 key。

服务端用同一队列串行处理变更和对账。订阅合并受影响 workspace 的变化，每 60 秒完整刷新补齐遗漏事件。客户端轮询不拥有归档定时器；状态变更先乐观展示，再按服务端结果确认或回退。

分组编辑和排序通过期望配置拒绝过时写入；任务编辑校验 `updatedAt`，状态转换校验请求所依据的受管理标签。受支持的宿主没有带条件的原子标签/归档操作，最终检查后仍可能发生原生界面并发修改。

客户端以发起控件 ID 跟踪待完成写入；同一控件重复提交会显示本地化拒绝提示，其它控件可并发请求，乐观并发安全仍由服务端保证。mutation 响应只有 revision 不旧于缓存时才替换缓存。确认弹窗收到 false 或异常时保留可见失败槽位。错误文案覆盖服务端所有静态错误及已知 issue；动态或未知错误使用本地化兜底。

成功跨分组移动共用 8 秒任务高亮；工具栏反馈条显示最近一次移动，即使任务被筛选隐藏、所在组折叠或视图切换也可撤销。撤销只发送反向 `stage` mutation，以成功移动后的受管理标签作为期望值；轮询发现卡片变化或窗口过期时失效，原生标签冲突时明确拒绝。不触碰归档路径或绕过门禁。冲突修复没有单一原分组，不能使用该反向操作；分组顺序仍通过反向重排恢复。

看板与列表共用一次查询、筛选、任务及分组顺序、乐观状态、待写入跟踪和撤销逻辑。列表纵向滚动保留空组、匹配数/总数和折叠投放目标，折叠状态独立保存；拖动落点按列表内容坐标和可见任务锚点计算，服务端仍校验完整未筛选顺序。看板拖入折叠目标会展开该列，列表投放后保留折叠。快速创建文本与错误按分组保存在视图切换层之上，仅成功创建后清空，因此切换或折叠不会丢失；切换视图也不中断已提交写入。筛选受控输入立即更新，客户端存储延迟 300ms 保存，离开时写入待保存的最新值。冲突提示遵循相同筛选并单独计数。看板列标题需 Alt/Meta+方向键才提交重排；列表把手使用 Alt+上/下方向键，也可用菜单上下移。Esc、窗口失焦、切换视图或筛选变化会取消未提交拖动。列标题的动作 label 表示打开分组选项，拖拽说明放 hint。tooltip 在关闭或卸载时清理定时器。Paseo 设置面板入口不展示返回看板。

## 草稿绑定

创建草稿只写插件数据。创建请求可指定任意待开始类型组；省略时使用默认待开始组。

开始工作会保存操作 ID，并使用 Paseo 幂等创建 workspace。可以创建不带 Agent 的 workspace，也可以关联已有 workspace。标签同步失败时保留绑定，重试不会再建 workspace；关联已导入 workspace 时合并到现有卡片并保留备注，同时记录原草稿 ID、标题、说明、合并时间及追加文本。`detach-draft` 校验幸存任务 `updatedAt`，只移除唯一匹配的原追加文本，恢复原 ID 的未绑定草稿并移除该来源记录；多条来源可各自恢复。文本已编辑或匹配不唯一、原 ID 已占用、幸存任务已归档时拒绝并保留数据和来源。失败后可按原意图重试，也可取消残留绑定；取消校验操作 ID，拒绝仍在执行或排队的绑定，不删除已创建或关联的 workspace。

## 自动化保护

侧栏自动置顶默认开启，按 `in-progress` 分组类型判断。插件记录 Paseo 返回的精确 `pinnedAt`，仅取消仍归自己拥有的置顶；已有或被手动替换的置顶保留。用户手动取消自动置顶后，任务本次处于进行中期间不会被再次置顶，离开并重新进入后才恢复自动行为。

自动归档默认关闭。已完成和已废弃类型组分别保存启用状态与等待期限；每条已启用规则都要求距离 workspace 所有 Agent 中最后一条已核实的用户或助手消息，严格超过该规则配置的期限（默认 30 天，整数范围 1–365）。缺少分状态期限时，使用共享的 `archiveAfterDays` 作为回退值。修改标签、编辑备注和导入 workspace 不重置时间。草稿及没有可信对话上界的 workspace 不具备资格。

每个 Agent 的对话存成两个互不替代的值：卡片展示用时间，和自动归档可用的门禁。展示证据可以是精确的用户/助手消息、下界（`≥`，来自 Paseo 记录的用户消息时间或部分回放窗口里较早的行），或上界（`≤`，Paseo 记录的活动时间）。门禁证据为精确时间，或以 Paseo 记录的活动时间作上界——它不会早于真实最后一条消息，因此只会推迟归档；下界永远不参与门禁。可信 inventory 首次观测到零 Agent 时，Workboard 在内存中记录该观测时刻作为上界，而非精确对话时间。连续可信的空 inventory 保留同一上界，归档复核也复用它；编辑任务和修改标签不改变该上界。观测到 Agent、Agent/provider 生命周期事件（包括两次轮询之间的创建再删除）、重启、断连、订阅失败或重新快照，以及 inventory 读取失败都会使上界失效，下次可信空观测重新计时。已有子 Agent 记录或带未解决原因的未知门禁仍保持未知；展示原因可能概括包括子 Agent 枚举在内的多个失败。删除最后一个 Agent 不会清除这些风险。Paseo 会用回放时的水合时刻重打历史行的戳，因此比记录活动时间更新的行按水合戳剔除，而不是让整个 workspace 失败；已记录的观测值也永远只作下界，不作门禁。

父 Agent 的 provider 子 Agent 无法枚举时，workspace 的归档门禁为未知；父 Agent 的旧活动时间或先前记录的子 Agent 清单均不足以放行，因为子 Agent 活动不一定更新父 Agent 时间。卡片保留已有显示证据，自动归档等待完整子 Agent 清单和可用的对话证据。已枚举但无法证明对话上界的子 Agent 同样阻止归档；已确认没有对话的子 Agent 不因此阻止归档。重启后以及真正归档前都执行相同检查。

已观察的子 Agent 不再出现在当前清单时，门禁保持未知。上次读取即使得到了精确时间、上界或空历史，也不能覆盖移除前新增消息的区间。持久化的子 Agent 观测时间只作显示证据，刷新、重启以及读取更早保存的记录时均不能用它放行归档；不额外持久化子 Agent 门禁字段。空历史例外只适用于仍在当前清单且本轮读取确认的子 Agent，也不会让本来没有对话的 workspace 获得归档资格。

订阅恢复后的 snapshot 和订阅请求失败会使子 Agent 清单缓存失效；provider 子 Agent 变更使其父 Agent 的缓存失效。失效时保留已观察的子 Agent，直到重新枚举成功；失效前发起的在途请求既不能回填缓存，也不能让本轮清单被视为完整，包括本轮已读取的其它父 Agent。活跃（running 或 waiting）且未归档的父 Agent 的子 Agent 枚举失败后，即使活动时间不变，也固定在 60 秒后重试。空闲父 Agent 在刷新里根本不枚举，只有归档复核才会列举它，其失败按指数退避（一分钟起翻倍，最长一小时，见下文）；已归档父 Agent 仍无法重新枚举。

Paseo 在响应任何按 Agent 的请求（时间线、provider 子 Agent 列表、子 Agent 时间线）前都会先加载该 Agent，且不会因空闲卸载 Agent。因此刷新只对活跃 Agent（running 或 waiting）发这类请求。空闲且未归档的 parent 不做枚举：它的子 Agent 标记为“已跳过”，这不是每 60 秒重试一次的“枚举失败”，所以空闲 parent 不会被定时重试。这类 workspace 的门禁保持未知，卡片显示记录的边界（`≥`/`≤`）并说明 Agent 处于空闲状态。被跳过 parent 名下已记录、但本次不在清单里的子 Agent 不算“消失”，只是因为 parent 没有被列举。从完整列举中消失的子 Agent、已归档 parent 和列举失败仍沿用上述规则。

空闲 parent 的记录时间连同已存的子 Agent 观测时间，只用来安排复核：当它按分组规则到期、且只有被跳过的空闲 parent 让门禁未知时，该 workspace 成为复核候选；它绝不授权归档。复核会重新列举每个空闲 parent 的子 Agent（列举失败或列举期间发生失效则延期），读取空闲 Agent 和每个列出的子 Agent，只有每一个都有可用上界且结果到期才归档；子 Agent 是否忙碌以这次新列举为准。复核即使最后延期，也可能把空闲 Agent 加载进内存，它们会保持加载直到被关闭。复核读到的较新子 Agent 时间写入已有的子 Agent 观测时间字段，它不授权归档，但会把下一次计划复核推迟到该时间之后，因此重复刷新和重启都不会重复同样的读取。复核失败在内存中退避（一分钟起翻倍，最长一小时）；重启会清空退避，仍然失败的到期候选在每次重启后再尝试一次。

Workboard 使用真实时钟。隔离集成套件可以请求仅用于测试的偏移（`WORKBOARD_TEST_CLOCK_OFFSET_MS`），使刚创建的 fixture Agent 被视为旧对话；它只在 Paseo home 是带集成标记的临时目录时生效，否则静默忽略。同时设置 `WORKBOARD_TEST_CLOCK_FILE=1` 后，带标记 home 内的测试可通过固定文件 `.workboard-clock-offset-ms` 推进偏移，无需重启插件。只接受不小于上次有效偏移的非负整数；文件缺失、内容无效或数值减小时保留上次偏移。生产时钟不读取该文件。快照会报告当前偏移，客户端的所有到期计算（设置预览、卡片到期日期）都使用它，因此界面显示与服务端判断一致。

调用原生归档前，服务端再次核对标签、活动和 workspace 安全状态。活跃 Agent、terminal、脚本、无法证明任何上界的历史或不安全 Git 状态会延期；Git 检查不会修补工作区或推送代码。超时或中断的归档意图记为结果未知，不盲目重试。成功必须同时有原生成功响应及刷新后退出活跃 workspace 清单的证据。

阻塞候选在进程内按原因退避，从 1 分钟翻倍至最长 1 小时。清单中与检查相关的状态变化会触发重新检查，检查时原因变化会重置退避。退避期间复用对话证据，不重复回放历史或执行 Git 检查；每轮扫描共用一次清单读取，但发送前和成功后的再次核对仍独立执行。重启会清除退避。

归档页可将结果未知或外部归档记录确认为已归档，或清除记录并放回看板。请求校验任务更新时间和归档操作 ID；原分组已删除时拒绝放回并保留记录。用户确认不会调用原生归档或捏造原生归档时间；放回看板保留 workspace 关联，缺席的 workspace 会显示不可用并保留任务，直到真实清单重新出现。此操作不会恢复原生 workspace 或目录，后续自动归档仍须通过所有门禁。草稿归档也可恢复，复用更新时间与操作 ID 校验；清除归档记录并回到原分组，原分组已删除或不再支持草稿时拒绝且保留记录。

原生归档可能停止 Agent/terminal 并清理托管 worktree。插件记录归档结果，但不保证目录清理或完整恢复；Paseo 原生合并后归档开关仍由 Paseo 管理。

设置保存会原子清除不再适用退避所属的警告，持久化成功后才移除内存退避；刷新也会在使用退避前核对规则。规则已关闭或已知对话门禁不再到期时可以清理，门禁未知本身不代表不再到期。保留独立任务问题；普通偏好保存不重读对话历史。

## 兼容边界

公开 SDK 尚未覆盖所有所需操作。兼容模块复用插件现有的已认证 IPC 会话，完成标签、置顶、settings 写入、启动初始化及部分历史/记录查询；不另建登录、不替换凭证、不修改 Paseo。

manifest 定义 Paseo 最低版本。桥接校验响应结构，但不固定宿主版本；后续版本可能需要适配。`.github/workflows/ci.yml` 的 CI 宿主矩阵声明流水线配置测试哪些 Paseo 版本；矩阵条目只表示测试意图，不表示已通过，只有实际成功的运行才能支撑兼容性结论。支持范围变化时，在 README、Cafe 信息以及引入该变化的 Release 说明中写明新范围和剩余边界。

运行时使用固定插件 ID `paseo-workboard`；安装时不要通过 `--id` 覆盖。

客户端使用 Paseo 提供的 React、React Native、TanStack Query、Zod 和插件模块；服务端使用宿主 SDK/Zod 与 Node 内置模块。发布包包含 TypeScript 源码，由 Paseo 处理，因此不需要构建步骤或安装运行时 npm 依赖。

## 客户端偏好

Paseo 没有公开插件语言 API。`client/paseo-language.ts` 只读 Web/Electron 的 `@paseo:app-settings` 语言，必要时回退旧 key，不写入宿主设置。它采用 Paseo 的系统语言选择规则，提供中文与英语文案。页面挂载期间通过 storage/focus 事件及每秒检查捕获同窗口语言变化。升级 Paseo 时须重新验证这一私有存储约定；没有该存储的客户端（包括原生移动端）回退到英语。

视图初始为看板，列表分组初始全部展开。视图选择、看板/列表各自的折叠状态、看板列宽和筛选按 host 存在浏览器 `localStorage` 中，与 daemon settings 分离；视图偏好不增加 RPC 或数据 schema 字段。存储失败不影响本次使用，不同客户端之间不自动同步。原生手机端的持久化和触控尚不在支持平台范围内。

修改这些边界的要求见[贡献指南](../../CONTRIBUTING.zh-CN.md)。

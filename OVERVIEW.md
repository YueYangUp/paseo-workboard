# Workboard

Workboard gathers active Paseo workspaces and unbound ideas into a task board and grouped list. One active workspace appears as one task; a title-only draft has no workspace until you create or attach one. You set task status. An Agent finishing a turn does not mark a task done.

Group the board by project to keep each project’s status columns together. Set High, Normal or Low priority on cards, then choose priority sorting or return to the saved default order. Settings lets you name and color each priority level; the task’s rank stays the same. Grouping, sorting and project folds are remembered per client and host.

Move tasks between groups to update their managed Paseo status labels, or change those labels in Paseo to update the board. Ordinary labels stay intact. Optional exclusive status labels resolve a new, identifiable status label against the previous one; ambiguous conflicts still need your choice. Board and list share tasks, filters, and saved ordering. Filter by project, attention, Agent activity, PR/MR condition, or last conversation date. Paseo supplies the PR/MR and CI information; Workboard does not query a forge separately.

Settings let you customize groups and their defaults, pin In progress workspaces in the sidebar, and enable automatic archiving. Archiving is off by default. Done and Canceled have independent switches and delays; turning both off stops automatic archive. Waiting-period controls stay visible and can be saved while a rule is off without enabling it. Changes that make tasks due show the full candidate list for confirmation before saving; canceling keeps the saved settings unchanged. When enabled, each rule waits for its configured delay after the last provable conversation and checks Agent, terminal, conversation, and Git safety before calling Paseo's native archive. Incomplete provider-child inventory, unbounded child history, or a previously observed child disappearing from the list postpones automatic archive while preserving the displayed conversation time. Subscription recovery requires a fresh child inventory before archive. Failed enumeration for an unarchived parent is retried after one minute. Native archival may stop Agents and terminals and remove a managed worktree; Workboard cannot restore one after removal.

Workboard requires Paseo 0.11.0 or later. Its daemon-side code uses the selected host's authenticated Paseo session to read workspaces, labels, conversation evidence, and Git safety data and to store task settings and perform requested host operations. View preferences and filters are stored locally in the client for that host. Starting a task does not create an Agent or send a prompt. Plugins run as trusted code on the daemon host. Upgrade notes for each version are in [GitHub Releases](https://github.com/fxbing/paseo-workboard/releases); setup and full usage are in the [README](README.md) and [user guide](https://github.com/fxbing/paseo-workboard/blob/main/docs/user-guide.md).
